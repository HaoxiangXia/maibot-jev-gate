# MaiBot Jev 门控预判插件 (maibot-jev-gate)

基于 TypeSafe / Liquid AI 结构化决策模型的 MaiBot 消息门控预判插件。

## 核心特性

### 1. 模糊区间门控（Ambiguity Band Gating）
- **触发机制**：摒弃对每条群聊消息全量调用外部模型的低效做法，引入自适应模糊区间门控。仅当本地门控先验概率与当前动态放行阈值的差值满足 $|P_{\text{local}} - \text{threshold}| \le \text{ambiguity\_margin}$（默认 `0.22`）时，才触发远程 Jev 预测。
- **核心收益**：明显不该回的消息（低概率）或极为笃定该回的消息（极高概率 / 直接 `@` 触发豁免）直接走本地零延迟判定；仅在本地门控“犹豫不决”的临界状态下借助 Jev 小模型裁决，削减 70% 以上的 API 调用量与额外耗时。

### 2. 置信度加权概率融合（Confidence-Weighted Probability Fusion）
- **计算机制**：根治原 PR 中二值化丢弃置信度的问题。提取 Jev 结构化返回的回复倾向概率 $P_{\text{jev}}$ 与决策置信度 $\text{confidence}$，按动态权重 $\alpha = \text{confidence} \times w_{\max}$ 执行概率融合：
  $$P_{\text{fused}} = \alpha P_{\text{jev}} + (1 - \alpha) P_{\text{local}}$$
- **核心收益**：将校正后的概率交还给宿主 `DynamicReplyTurnGate` 与本地动态阈值裁决，完整保留用户在 WebUI 设定的 `talk_value` 回复频率滑块及前馈/反馈频控算法，杜绝密集闲聊群中模型因频繁判定可回复而无节制发言的问题。

### 3. 静默已读游标推进（Silent Consume）
- **解决痛点**：群聊长期不触发回复时，宿主缓存的未处理消息游标 `_last_processed_index` 会停滞不前，导致后续轮次重复携带旧消息甚至因超出上限被迫强制唤醒 Planner 泄洪。
- **处理机制**：当 Jev 在模糊区间内以高置信度（默认 `confidence >= 0.72` 且倾向为 `consume_silent`）判定当前消息纯属背景杂音、他人私聊或无意义刷屏时，向宿主返回 `decision="consume"`。
- **核心收益**：宿主直接推进 `_last_processed_index`、将消息同步写入聊天历史（确保后续上下文记忆不断层）并按需裁剪缓存，**完全不唤醒任何下游 Planner**，优雅消除消息堆积。

### 4. 多预设管理与无损切换（Profiles & Presets）
- **灵活切换**：在 WebUI 中提供结构化预设列表，可同时保存 TypeSafe 官方、第三方中转或自建代理等多套服务商配置（包含独立 `api_key`、`base_url`、`model` 与超时时间）。
- **无损保存**：通过 `active_profile` 即可一键切换当前生效的配置项，切换服务商无需覆盖原有参数，随时一键切回。

## 推荐配置与调优建议

1. **群聊回复频率建议设置在 `0.4 ~ 0.6`**：
   - **避免设为 `1.000`**：当回复频率拉到满格 `1.000` 时，主程序本地动态门控会将放行阈值强制降为 `0.00`，导致哪怕只有 0.35 概率的消息也会因 $|0.35 - 0.00| = 0.35 > 0.22$ 判定为“确定放行”而跳过 Jev 预判。
   - **最佳表现**：将频率滑块置于 `0.4 ~ 0.6` 时，本地动态阈值通常维持在 `0.30 ~ 0.50` 附近。此时大部分非 `@` 的临界消息都会精准落入模糊区间（$|P_{\text{local}} - \text{threshold}| \le 0.22$），充分调起 Jev 进行语义把关。
